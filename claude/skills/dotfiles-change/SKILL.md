## The repo is not the live config

`~/projects/ConfigMe` is the source of truth and everything is symlinked out of
it, so editing the repo edits the live config. Two things do not follow from
that, and both have bitten before:

**A running tmux server never re-reads its config.** Editing `tmux/.tmux.conf`
changes nothing in an existing session. Apply with `prefix + R` (`C-Space` then
`R`), then verify against the running server rather than the file:

```bash
tmux show-options -g <option>
```

Checking an isolated server instead (`tmux -L test -f ...`) proves the file is
valid but says nothing about the session actually in use. Do both: the isolated
server to validate, the live one to confirm it applied.

**kitty reads its config at startup.** Changes need a new instance, and
`allow_remote_control` / `listen_on` in particular only take effect at launch.

## Adding a new tool

1. Put the config under a directory named for the tool.
2. Add a `link` call in `install.sh`, inside the right platform branch. Not
   every tool exists on every platform.
3. If it needs a system package, add it to `packages/apt.txt` **with the reason
   in the comment**. If apt cannot provide it, document the install in
   `packages/manual.md` instead.
4. If it fails silently when absent -- no error, just wrong behaviour -- add a
   check to `doctor()` in `install.sh`. That is what the doctor is for.
5. Machine-specific values do not belong in the repo. kitty reads
   `local/*.conf`, generated by `install.sh`.

## Keybindings

Any new binding goes in `KEYBINDINGS.md`. If it overrides a default, add it to
the "Changed from defaults" table with the reason -- a surprising binding needs
more explanation than a new one.

Check for collisions before binding. In tmux, plugin bindings load after this
config and win, so consult the plugin-owned table; a `last-window` binding was
silently lost to tmux-sidebar this way.

## Finishing

```bash
./install.sh            # apply
./install.sh --doctor   # confirm nothing broke
```

Then commit. The Windows checkout at `C:\Users\maxwa\ConfigMe` is a read-only
mirror and does not update itself:

```bash
cd /mnt/c/Users/maxwa/ConfigMe && git pull wsl main
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\install.ps1"
```

Re-running `install.ps1` is only needed when the change affects a Windows
target. nvim is a junction, so nvim changes are live there after the pull alone.

Never push without being asked.
